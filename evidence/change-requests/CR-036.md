# CR-036 — A more natural French read-aloud option

**Received:** 26 November 2026  
**Status:** Neural reader implemented on `main`; made the default in Loop 037. Quality pipeline and physical-device listening are still pending.

## Request
The existing French reader still sounds unpleasantly mechanical. Improve its quality without relying on a French voice installed on the visitor's device or sending association page text to a third-party speech service.

## Findings
The current lightweight reader uses eSpeak NG. It is dependable and small, but its synthesized timbre is recognizably mechanical. Browser-installed voices cannot guarantee a French voice on every visitor device.

## Implementation
- Added an optional neural French reader based on Kyutai Pocket TTS, executed in a module worker with ONNX Runtime Web and one WebAssembly thread.
- Used a pinned 8-bit French browser bundle, with the French voice state from Stuart Bell's Voice-Zero/LibriVox material. The model manifest and downloaded files are verified by SHA-256; model files are cached by the browser when storage permits.
- Initially kept eSpeak NG as the small default and fallback. In Loop 037, Pocket TTS became the default reader; the model still loads only when the visitor starts reading, while eSpeak NG remains an explicit fallback.
- Disclosed the approximately 134 MB first-use download, local synthesis, optional caching, performance trade-offs and source licences on the Accessibilité page.
- Added French text normalization, tokenizer and voice-control regression checks.

## Validation boundary
The neural model has not been auditioned on the user's or association owner's physical devices in this session. Its actual timbre, pronunciation, volume and playback responsiveness on older phones remain to be confirmed. Automated checks can prove that the code builds and controls work, but cannot prove that the voice sounds pleasant. No production deployment was performed.
